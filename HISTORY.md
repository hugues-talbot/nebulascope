# NebulaScope — a development history

*A chronicle of how this software came to be: the arcs, the decisions, and
the reasoning behind them. Written from the collaboration between Hugues
Talbot and Claude (Anthropic), which built NebulaScope from first commit to
the releases described below. Companion documents: `docs/DECISIONS.md` for
point-form design decisions, `docs/RELEASES.md` for the release notes,
`TODO.md` for direction. This file records the* story.

---

## Inception (26 June 2026)

NebulaScope began with a narrow thesis: astronomical software is excellent
at *processing* and mediocre at *looking*. PixInsight and Siril stretch,
calibrate and integrate superbly, but neither is a fast, precise,
annotation-centric **inspector** — and SAOImage DS9, the venerable
inspector, has dated stretch ergonomics. The gap: a tool whose heart is a
draggable, per-channel RGB histogram with modern transfer functions, that
never modifies the data it displays.

Three principles were set on day one and never violated:

1. **Raw data are never modified by display operations.** Everything the
   user sees is a view; every "result" that isn't is a new list entry.
2. **One code path.** Everything is promoted to 32-bit float at load; FITS,
   XISF and ordinary pictures flow through the same pipeline.
3. **Precision over convenience.** Full-float transfer across the window,
   dithered 8-bit output, no posterization however narrow the window.

## The foundation (v0.5 – v0.81, June–July 2026)

The histogram panel came first — Linear/Log/Asinh and the Generalised
Hyperbolic Stretch with draggable symmetry-point and protection handles —
followed by the annotation layer (pure vector, never rasterized, persisted
in JSON sidecars), SExtractor catalog import, WCS astrometry with grid and
hover readout, linked split views, and blink with per-image stretch memory.
The "linked views" idea grew into *calibrated* linking: align two views of
different pixel scales once, and they navigate together thereafter — which
later became the tool's signature way of comparing instruments.

Distribution arrived pragmatically: GitHub Actions building macOS, Linux
and Windows, a .deb, releases assembled by CI (v0.72–v0.80).

## Colour transport (v0.82, then again and again)

The first "unique feature": recolour an image to match a reference's
palette by sliced optimal transport (Pitié's iterative distribution
transfer), estimated only from the pixels visible in each view. It worked —
and field use immediately exposed its costs: tie-collapse posterization and
noise amplification, both *inherent* to empirical histogram mapping. The
response became a pattern for the whole project: derive the failure
mathematically (the noise law T′ = f_s/f_r, documented in the book), then
design around it — the **stretch fit**, which fits the display stretch to
match the transported look with zero data loss, later gaining intensity
weighting and a cross-channel colour-adjust stage. The mathematics went
into the manual as a chapter, not a comment.

## The documentation turn (v0.86 – v0.89, late July 2026)

After v0.86, a deliberate pause: "consolidate documentation and testing
before new features." Four workstreams, in order: a headless smoke test in
CI (the `.nsc` script language was born as a test harness and became a
user-facing scripting feature); unit tests for the core; PixInsight interop
fixtures; and a Quarto book — title page, bibliography, build guides,
release notes — with **every screenshot generated by the app's own
scripting from real acquired data**. The standing convention dates from
here: *features land with manual section, screenshot and tests in the same
change.* It held through everything that followed, in two languages.

## Field-driven development (v0.90, 30 July 2026)

The decisive methodological turn: use the tool at the telescope and let
friction set the roadmap. In quick succession, all from bench reports:
OSC **debayering** (RCD validated numerically against Siril's
implementation), auto-reload of files overwritten by external tools,
fast batch opens, shared STF ("Apply to All"), stretch-function keyboard
shortcuts — and **blink culling**: keep-checks on every list row, B to
reject a frame mid-blink, then sort/move/remove by tag. The thesis "a
better Blink than PixInsight's" was validated in the field within days,
running the per-filter loop: load, Auto STF, Apply to All, blink, cull,
clear, next filter.

## Bilingual (v0.91, 1 August 2026)

"My users are very likely to be French speakers." In one arc: every
user-visible string wrapped and translated (443 messages), system-locale
default with a Preferences override, a standalone French Quarto book
(préface, manual, transport chapter in native French), a bilingual site and
two release PDFs. Two decisions worth recording: the `.nsc` script language
and CLI output **stay English** as a locale-independent API (scripts must
run identically everywhere — and `dlgclick` matches visible text, so
script-addressable controls keep English labels); and lupdate's unqualified
contexts against Qt's namespace-qualified runtime lookup — every
translation would have silently failed — was caught by an embedded A/B
probe before a single string shipped.

v0.91 also fixed the release plumbing itself: notes are written once, in
the annotated tag, and flow identically to the GitHub release page, the
manual's appendix, and both PDFs. (Two CI traps were disarmed on the way:
actions/checkout silently peels annotated tags, and the release action
never overwrites an existing release body.)

## Ergonomics sprints (v0.92, 3 August 2026)

A cascade of small field reports, each a one-day fix: drag a list row onto
a view cell; the list holds each image once; batch opens fill empty cells
in the order given; ⌥C clears list and views; ⌥F is the green button on a
key; every file dialog starts in the current image's directory; save
options (depth/quality/XISF compression) moved *into* the save dialogs;
saved in-memory results take the file's name on every save path. Plus one
subtle display fix with a story: a "strange square pattern at some zoom
levels" turned out to be nearest-neighbour minification phase-locking with
CMOS fixed-pattern noise — moiré, cured by direction-dependent sampling
(bilinear zoomed out, crisp pixels at 1:1 and beyond).

## The SPCC saga (v0.93, 5–6 August 2026)

The richest arc, and the best illustration of the method. It began with a
modest question: *why does my SPCC-calibrated image look uncalibrated in
NebulaScope?* — and unravelled, over three days of field reports, into:

- **DisplayFunction import**: XISF carries the producing application's
  saved screen stretch; NebulaScope now applies it on first view, so a
  PI-processed image opens looking as it did on PI's screen.
- **ICC handling**: embedded profiles honoured (the field file's turned
  out to be plain sRGB — the transform correctly does nothing), and the
  real colour gap found *monitor-side*: Qt paints untagged on wide-gamut
  panels; on macOS the window now declares sRGB and the OS converts.
- **Resolution bugs** exposed by PI's far-out white points: the transfer
  LUT under-resolving the MTF toe (adaptive resolution), the curve overlay
  drawing staircases (exact evaluation), colour transforms re-banding
  dithered output (transform inside the pipeline, dither last).
- **The Möbius rebase**: PI's STF lives on the [0,1] container, parking
  imported white points 80–300× beyond the data and breaking every
  histogram control. The fix is closed-form: the MTF family is exactly the
  Möbius maps fixing 0 and 1, hence *closed under restriction and
  renormalisation* — the imported curve rebases onto the data range with
  no approximation, against one common output level so calibrated channel
  balance survives untouched. The derivation is an appendix in the book,
  at the user's request.
- **Two genuine bugs caught by the user's eyes**: per-channel rescaling
  would have silently re-white-balanced (fixed before it shipped), and the
  linked histogram drag had *always* ratcheted channel offsets apart via
  per-channel clamps — invisible until imported midtones sat just above
  black; now the group moves rigidly and drags are exactly reversible.
- **The resolution of the original mystery**: the file's saved STF was
  *unlinked* (channel-equalizing — it visually cancels SPCC's calibration).
  Confirmed by cross-testing in PI itself: NebulaScope-untouched matches
  PI's unlinked button; NebulaScope + Shift+U matches PI's linked button.
  The status bar now says so when it happens: *unlinked STF — Shift+U
  preserves calibrated colour.*

Alongside: stretch **undo history** (gestures coalesce into single steps,
⌘Z walks back to the as-loaded state) and **Reload Original** (⌘⇧R) —
because once a file can bring its own stretch, backing out of it must be
one keystroke. And a synthetic-fixture harness (`assert stretch`, crafted
XISF files with known DisplayFunctions) so the whole import pipeline is
regression-tested without a fiddly PI session in the loop.

Also in v0.93: the ten classic **DS9 palettes**, reproduced from DS9's
reference control points — the project's first feature landed on an
outside user's request — and exact build provenance (`git describe` in the
About box and `--version`), so a test binary always names its commit.

## Between the milestones

Some of the project's texture lives outside the feature list. The same
week the SPCC saga ran, the tool photographed **SN 2025rbs in NGC 7331**
through a 180 mm camera lens and through a C11 — the calibrated-link
comparison of those two became the manual's §12 illustration, real data
carrying a real story. The Andromeda luminance from the 80/480 apo
provoked the observation that fair instrument comparisons need the same
mount. A WBPP mystery (checkerboard + 180° rotation) was diagnosed from
first principles as a FITS orientation flip changing Bayer phase — and
turned out to be a single mis-set PixInsight preference.

## The method, in retrospect

What made the pace possible (v0.0 to v0.93 in six weeks) was less any
single feature than a working loop:

1. **Field report** — a precise observation from a night at the bench,
   often with a screenshot.
2. **Mechanism, not symptom** — derive why, mathematically where possible;
   the derivation goes in the book, not just the commit message.
3. **Fix + test + bilingual docs in one change** — the standing
   convention; nothing lands half-documented.
4. **Verify reproducibly** — scripted captures, numeric assertions,
   fixtures; CI green on three platforms before any tag.
5. **Release notes written once** — in the annotated tag, flowing to the
   release page, the appendix, and both PDFs.
